# Perfect Note audit - 2026-09-18

Reviewed every line of the active application, stylesheet, regression checks, and README, plus the installed Hyprland rule and desktop launcher. Historical backup copies and generated bytecode are not active application code. Existing saved-note structure was checked without printing its contents.

## Fixed findings

| Area | Confirmed problem | Fix |
| --- | --- | --- |
| Clipboard | A delayed clipboard response could replace a selection made after the paste request. Responses could arrive out of order. | Capture the original insertion/selection with text marks, validate it before replacement, and apply queued responses in request order. |
| Segment ranges | Pasting inside another paste created overlapping ranges; deleting the outer segment could remove both. | Split the original range around the new paste; surviving pieces keep their original dates. |
| Undo/redo | Intermediate states in a grouped action and repeated document text could restore the wrong timestamps. | Snapshot complete user actions and match GTK replayed character counts as well as text. |
| Replacing words | Replacing the first word or entire text of a segment could drop the replacement from that segment. | Preserve the segment date and boundaries through a replacement action. |
| Deleting segments | Deleting the last segment could remove a newline belonging to the preceding paste. | Only remove a separator that is outside other segments. |
| Unicode | Decomposed accents, emoji families, and flags were split into individual code points during word selection. | Build word selections from GTK cursor/grapheme boundaries. |
| Loading/backups | A failed backup write could blank a valid note while retaining stale ranges. A broken text export could prevent loading valid JSON. | Separate validated loading from best-effort binary backups; clear metadata on genuine load errors. |
| Invalid data | Fractional/bool offsets and embedded NUL/surrogate text were accepted or silently truncated. | Validate schema, ranges, ordering, dates, and text before giving data to GTK. Never overwrite invalid source files. |
| Atomic writes | A fixed temporary filename could collide with another file and remain after failure. | Use a unique private temporary file, clean it on failure, and retain atomic replace/fsync behavior. |
| Shutdown | SIGTERM/SIGINT could exit despite unsaved edits after a storage failure. | Refuse normal exit until saving succeeds; finish pending clipboard requests before quitting. |
| Selection state | Native cursor changes could leave a stale marked-segment state. Deleting the final word could leave a nonfunctional whitespace selection. | Clear stale navigation state and fall back to selecting the remaining whole segment. |
| Gutter | Joining segments on one text line caused overlapping timestamp labels and click targets. | Share stacked label geometry between painting and hit-testing, with enough scroll space. |
| Reopening | An indented but otherwise empty final line caused extra newlines on reopen. | Reuse whitespace-only final lines. |

## Verification

- Python syntax compilation and the full regression suite passed.
- Temporary-note checks cover migration, local save/reload, backups, malformed data, write failures, clipboard ordering, selection changes, Unicode, split segments, timestamp identity, keyboard navigation, wrapping, copy/delete, and undo/redo.
- Randomized edit/undo/redo runs passed with 150 cycles (seed 91826) and 500 cycles (seed 47119).
- A separate child-process test sent actual SIGTERM during a simulated storage failure, verified that the process stayed alive, restored storage, and verified that the next SIGTERM saved the note and exited cleanly.
- A temporary sample window was inspected at 638 x 845 pixels, including segments sharing a text line. The real note was not used as sample content.
- The desktop entry passed `desktop-file-validate`; Hyprland reported no configuration errors.
- GTK's [official text-history implementation](https://github.com/GNOME/gtk/blob/main/gtk/gtktexthistory.c) was checked to verify that merging actions preserves the number of inserted/deleted characters used to track timestamp history.

Run the normal checks with `python check.py`. Repeat the longer run with `PERFECT_NOTE_TEST_SEED=47119 PERFECT_NOTE_TEST_CYCLES=500 python check.py` in a desktop session. Checks use temporary notes and clipboard stubs, and briefly display a sample window. They do not replace the regular clipboard contents.

The tests do not simulate power loss, SIGKILL, disk hardware failure, or every clipboard provider. Undo remains session-local. The note and its backup files are local files, not an independent off-machine backup. No new dependencies, shortcut changes, or data-format version changes were introduced.
